# Make Knowledge Cards

把一篇文章（用户粘贴的文本，或本地 .md / .txt 文件）转换成一组知识卡片，每张卡片只承载一个真正重要的知识点。

## 支持的输入与边界

- 输入：用户直接粘贴的文章文本，或本地 Markdown（.md）、TXT（.txt）文件的路径。
- 读取文件：用 Read 工具完整读取文件，不要只读片段或靠标题猜测内容。
- 不支持的输入：网页链接（不做抓取）、PDF、Anki 导入、图形界面制作。遇到这些需求，明确告知不支持，不要尝试转换。

## 工作流程

1. 通读全文，理解文章主题、结构以及作者真正要传达的内容。
2. 逐段提炼知识点：记录每个独立且重要的知识点，包括概念、原理、机制、方法、关键数据、因果链条、可操作步骤。
3. 合并与去重：同一知识点在不同段落重复出现时合并；删除不承载知识的文字（客套话、冗余举例、与主题无关的段落）。
4. 筛选与排序：按"对理解文章主题的重要性"排序，而不是按出现顺序。选出最重要的 5~8 个知识点。
5. 逐张写卡片，每张卡片只写一个知识点。
6. 按"质量自检清单"逐项检查并修正后输出。

## 卡片结构

每张卡片必须包含四个字段：

### 卡片 N：<标题>

- **核心知识**：一句话讲清这个知识点的本质，用自己的话概括，可引用原文关键句。
- **简明解释**：2~4 句话展开，说明"为什么、怎么用、和什么相关"，全部来自原文。
- **例子或自测问题**：优先写例子——必须取自原文或直接由原文推导；原文没有可写例子时，改写成只能根据原文回答的自测问题。

标题要求：不超过 15 字，能独立传达知识点，避免"文章里的某个概念"这类模糊标题。

每张卡片必须自洽：不依赖上下文也能读懂，不要在卡片内出现"如上文所述""文章前面提到"这类指代。

## 选点规则

- 只选重要知识点：定义、原理、机制、方法论、关键数据、因果链条、操作步骤。跳过个人观点、逸事、客套话、与主题无关的内容。
- 小说、故事、章节类文本的"重要知识点"是人物与人物关系、环境设定、关键情节、主题线索，按同样的数量和忠实规则输出。
- 一卡一点：以"读者能否独立理解"为准决定拆分或合并；不同的知识点绝不合并进一张卡。
- 数量：5~8 张。信息不足（短文、知识点少于 5 个）时按实际输出 2~4 张甚至更少，不要为凑数拆分、注水或编造。
- 全文没有可独立成卡的实质知识时，输出一张说明卡片："本文信息量不足，无法生成知识卡片"，并简要说明原因。

## 忠实原文规则

- 所有核心知识、解释、数字、结论必须能在原文中找到依据。
- 禁止编造：不添加原文没有的事实、数据、案例、定义；不从原文外推新结论。
- 原文表述模糊或缺失的信息，不猜测、不补全；确实需要补充说明的地方，标注"原文未说明"。
- 原文内部出现矛盾或明显笔误时，如实摘录，并标注"原文如此"，不要擅自替原文修正。

## 输出格式

默认直接在回复中输出 Markdown 卡片列表，开头给一行总览：

> 来源：<文章标题或文件名> ｜ 卡片数：N

然后按"卡片 1…卡片 N"逐张输出。用户要求保存时，再把卡片写成 .md 文件交付。

## 质量自检清单

输出前逐项检查：

- [ ] 每张卡片是否只讲一个知识点
- [ ] 是否有重复内容（跨卡片或卡片内）
- [ ] 是否编造了原文没有的信息
- [ ] 是否强行凑到 5 张以上（短文应更少）
- [ ] 四个字段是否齐全，标题是否清晰
- [ ] 每张卡片是否自洽，不依赖上下文也能读懂
- [ ] 原文的矛盾或笔误是否如实标注，而非擅自修正
- [ ] 例子是否来自原文；自测问题是否只能由原文回答
